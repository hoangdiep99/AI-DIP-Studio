LƯU Ý QUAN TRỌNG
--------------------------------------------------------------------
- Trang https://aivideoauto.com/ là một Single Page App (React), không
  công khai tài liệu API dạng văn bản trên URL đó — bản thân trang chỉ
  trả về HTML + JS bundle của ứng dụng web.
- Tài liệu dưới đây được tổng hợp lại bằng cách đọc mã nguồn thực tế
  của app (các file lib/api.js, lib/generate.js, lib/mediaJobs.js,
  lib/modelCatalog.js, lib/autoai.js) — đây chính là cách app hiện tại
  đang gọi API của hệ thống AI VIDEO AUTO / Gommo.
- Nếu nhà cung cấp có trang tài liệu API chính thức riêng (ví dụ dạng
  Swagger/Postman), hãy cho biết URL cụ thể để mình tổng hợp thêm.


1. TỔNG QUAN HỆ THỐNG
--------------------------------------------------------------------
Ứng dụng hỗ trợ 3 chế độ kết nối API (config "mode"):

  a) "system"  — Gọi qua Gommo Mini App Bridge (window.gommoMiniApp.call)
                 khi app chạy nhúng trong hệ thống AI VIDEO AUTO.
  b) "custom"  — Gọi trực tiếp Google Gemini API bằng API Key cá nhân
                 của người dùng (không qua server trung gian).
  c) "openai"  — Gọi tới nhà cung cấp tương thích chuẩn OpenAI
                 (ví dụ RunningHub, laozhang.ai) bằng API Key riêng.

Ngoài ra còn 1 lớp gọi API dùng chung "gommoApi()" — tự động thử nhiều
host/backend (fallback) khi không dùng bridge:
  - https://api.aivideoauto.com
  - https://api.gommo.net
  - window.location.origin (origin hiện tại của app)

Base URL mặc định (customEndpoint): https://api.aivideoauto.com


2. XÁC THỰC (AUTHENTICATION)
--------------------------------------------------------------------
Có 2 cách xác thực chính, gửi kèm mỗi request:

  - access_token: gửi trong body/query dưới dạng field "access_token",
    HOẶC gửi qua header "Authorization: Bearer <access_token>".
  - domain: field bắt buộc gửi kèm mỗi request — là "domain/app slug"
    của ứng dụng trên hệ thống AI VIDEO AUTO / Gommo (KHÔNG phải domain
    của server API). Nếu access_token hợp lệ mà domain sai sẽ gặp lỗi
    dạng "Cant access #1".
  - x-api-key: nếu KHÔNG có access_token, app có thể gửi Gemini API Key
    qua header "x-api-key" (chỉ dùng cho luồng gọi trực tiếp Gemini).

Content-Type mặc định cho các request POST: application/x-www-form-urlencoded

Ví dụ header khi có access_token:
  Authorization: Bearer <ACCESS_TOKEN>
  Content-Type: application/x-www-form-urlencoded

Body mẫu (form-urlencoded):
  access_token=<token>&domain=<domain-app>&<...other params>


3. DANH SÁCH ENDPOINT (theo lib/api.js, lib/generate.js, lib/mediaJobs.js, lib/autoai.js)
--------------------------------------------------------------------

3.1. Lấy thông tin tài khoản / số dư Credits
  POST /api/apps/go-mmo/ai/me          (endpoint chính, ưu tiên)
  POST /ai/me                          (dự phòng)
  POST /api/me                         (dự phòng)
  (App cũng thử lại bằng GET nếu POST không thành công)

  Body: { access_token, domain }
  Response (rút gọn, dạng JSON):
  {
    "balancesInfo": { "credits_ai": <number>, ... },
    "userInfo": { "name", "email", "phone", ... },
    "currentSubscription": { "name", "status", ... }
  }
  Ghi chú: App tìm số dư credit bằng cách quét nhiều field khả dĩ:
  balancesInfo.credits_ai, balancesInfo.credit_ai, balancesInfo.credits,
  balancesInfo.balance, credits, credit, balance, wallet.balance, v.v.

3.2. Lấy danh sách Model AI (ảnh)
  POST /ai/models
  (Dự phòng thử thêm): 
    GET/POST /api/apps/go-mmo/ai/models
    GET/POST /api/apps/go-mmo/models
    GET/POST /api/apps/go-mmo/ai/model-list
    GET/POST /api/apps/go-mmo/ai/model
    GET/POST /ai/model/list
    GET/POST /api/v1/models

  Body gửi kèm: { type: "image", access_token, domain }
  Response (rút gọn):
  {
    "success": true,
    "data": [
      {
        "id_base": "google_image_gen_banana_2",
        "model": "google_image_gen_banana_2",
        "name": "Nano Banana 2",
        "description": "...",
        "server": "Google_veo",
        "status": "ON",
        "ratios": [ { "type": "1:1", "name": "1:1" }, ... ],
        "resolutions": [ { "type": "1k", "name": "1K" }, ... ],
        "modes": [ { "type": "vip2", "name": "vip2" }, ... ],
        "price": <number optional>
      },
      ...
    ]
  }

3.3. Tạo ảnh AI (Generate Image)
  POST /ai/generateImage

  Body (application/x-www-form-urlencoded):
  {
    action_type: "create" (hoặc theo model.action_type),
    sync: "false",
    model: "<model id_base hoặc model>",
    prompt: "<nội dung prompt>",
    privacy: "PRIVATE",
    ratio: "<vd 1:1, 3:4, ...>",          // nếu model hỗ trợ
    resolution: "<vd 1k, 2k, 4k>",         // nếu model hỗ trợ
    mode: "<vd standard, fast, vip2>",     // nếu model hỗ trợ chế độ
    editImage: "true",                     // chỉ gửi khi có ảnh gốc để sửa
    base64Image: "<base64 ảnh gốc>",       // chỉ gửi khi editImage = true
    access_token, domain
  }

  Response tạo job (dạng bất đồng bộ):
  {
    "imageInfo": { "id_base": "<jobId>", "status": "PENDING_ACTIVE", ... }
    // hoặc "data": { "imageInfo": {...} }
  }
  App lấy "jobId" từ imageInfo.id_base / id / image_id để polling kết quả.

3.4. Kiểm tra trạng thái / lấy kết quả ảnh (Polling)
  POST /ai/image

  Body: { id_base: "<jobId>", id: "<jobId>", access_token, domain }
  Polling định kỳ mỗi 15 giây (lần đầu chờ ~1.2s), timeout tối đa 3 giờ.

  Response:
  {
    "imageInfo": {
      "id_base": "<jobId>",
      "status": "SUCCESS" | "PENDING_ACTIVE" | "PROCESSING" | "ERROR" | ...,
      "url": "<link ảnh kết quả>",
      "download_url": "<link tải xuống>"
    }
  }
  Trạng thái SUCCESS -> lấy url/download_url làm kết quả cuối.
  Trạng thái lỗi (ERROR, FAILED, LIMIT_TIME, CANCELLED...) -> ném lỗi,
  hiển thị message tương ứng (vd "Hết thời gian xử lý (Limit Time)").

3.5. Tạo Video AI (Generate Video) — theo lib/autoai.js
  POST /ai/create-video
  Body: { model, prompt, ..., access_token, domain }

3.6. Kiểm tra trạng thái Video
  POST /ai/video
  Body: { id_base / videoId, access_token, domain }

3.7. Danh sách Video đã tạo
  POST /ai/videos

3.8. Upload ảnh (một số luồng dùng riêng)
  POST /ai/image-upload
  Body: { base64Image, access_token, domain }


4. QUY TẮC TỰ ĐỘNG DÒ HOST (FALLBACK LOGIC) — lib/api.js: gommoApi()
--------------------------------------------------------------------
Khi không chạy trong Bridge (chế độ "system"), app thử endpoint theo
thứ tự các host sau, dừng lại ngay khi có response HTTP OK:

  - Trên môi trường dev (localhost, npm run dev):
      /api-proxy/aivideoauto
      /api-proxy/gommo
    (Do CORS chặn gọi trực tiếp domain thật từ localhost, Vite dev
     server có proxy nội bộ định nghĩa trong vite.config.js)

  - Trên production:
      customEndpoint (mặc định https://api.aivideoauto.com)
      https://api.aivideoauto.com
      https://api.gommo.net
      window.location.origin

  Với mỗi host, app còn thử thêm 2 biến thể path nếu endpoint không có
  tiền tố sẵn:
      <host><endpoint>
      <host>/ai<endpoint>
      <host>/api<endpoint>

6. TRẠNG THÁI JOB (STATUS) CHUẨN HÓA — lib/mediaJobs.js
--------------------------------------------------------------------
Ảnh (image):
  - Thành công: SUCCESS
  - Đang xử lý: PENDING_ACTIVE, PROCESSING, PENDING_PROCESSING, PENDING

Video:
  - Thành công: SUCCESS, SUCCEEDED, COMPLETED, COMPLETE, DONE, FINISHED,
    READY, RENDERED, GENERATED, MEDIA_GENERATION_STATUS_SUCCESSFUL,
    SUCCESSFUL
  - Đang xử lý: PENDING, PENDING_ACTIVE, PENDING_PROCESSING, PROCESSING,
    ACTIVE, QUEUED, IN_QUEUE, WAITING, RUNNING, IN_PROGRESS, CREATED,
    SUBMITTED, STARTED, MEDIA_GENERATION_STATUS_PENDING/ACTIVE/
    PROCESSING/RUNNING

Thất bại (cả ảnh & video): ERROR, FAILED, FAIL, LIMIT_TIME, TIMEOUT,
  TIMED_OUT, CANCELLED, CANCELED, REJECTED, UNKNOWN,
  MEDIA_GENERATION_STATUS_FAILED, PUBLIC_ERROR_VIDEO_GENERATION_TIMED_OUT

Vi phạm chính sách: status hoặc message chứa "UNSAFE" hoặc
  "PUBLIC_ERROR_UNSAFE_GENERATION" -> hiển thị "Vi phạm chính sách".

8. GHI CHÚ TRIỂN KHAI / LỖI THƯỜNG GẶP
--------------------------------------------------------------------
- Lỗi "Cant access #1": thường do gửi sai "domain" (phải là domain/app
  slug cấu hình trên hệ thống AI VIDEO AUTO, không phải domain server API).
- Lỗi "Failed to fetch": do CORS/network — cần chạy qua proxy dev
  (vite.config.js) hoặc dùng Bridge (chế độ "system") khi nhúng trong
  mini app thật.
- access_token để RỖNG sẽ báo rõ trong debug info của app: "(RỖNG — chưa
  nhập Access Token trong phần Cấu hình!)".
